> **TL;DR**：Pikachu 仓库自带的 Dockerfile 已经不能用了（基础镜像只剩 arm64、依赖的 Debian bullseye 安全源已下架）。
> 本文记录我最后跑通的路线：**官方 `php:7.4-apache` + 完全不碰 apt + 数据库独立成 `mariadb:10.6` 容器**，全程约 10 分钟。
> 中间踩的四个坑，每一个的排查过程都比结论更值得记。

## 0. 写在前面

### 0.1 这次要做什么

在 **Kali 虚拟机**里用 Docker 跑起 **Pikachu（皮卡丘）** 靶场，目标是：

1. 浏览器打开 `http://127.0.0.1:8080` 能练题；
2. 打崩了能一键回到干净状态；
3. 靶场不能暴露到局域网，更不能暴露到公网。

### 0.2 Pikachu 是什么

一个**故意写满漏洞**的 PHP Web 应用，用于练习 Web 渗透。模块覆盖：暴力破解、SQL 注入、XSS、CSRF、文件包含/上传/下载、RCE、越权、目录遍历、敏感信息泄露、PHP 反序列化、XXE、URL 重定向、SSRF 等。

它是"教学用的假靶子"，不是真实业务系统——但也正因为如此，**它比任何真实系统都危险**：一旦别人扫到，等于白送一台随便打的机器，而这台机器在你自己网络里。

### 0.3 四个坑提前看

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | `exec /bin/sh: exec format error` | 加速器只给了 `linux/arm64` 的基础镜像 | 放弃仓库 Dockerfile，换官方基础镜像 |
| 2 | `apt-get install` 大量 `404 Not Found` | Debian bullseye 安全源的 pool 文件已清空 | 换源没用，**彻底不装 apt 包** |
| 3 | `sed` 改完配置页面仍连不上库 | `config.inc.php` 用的是 `define()` 常量，不是 `$dbhost` 变量 | 改正则，并 `grep` 验证 |
| 4 | `using password: NO` | `DBPW` 的值是空字符串 | 显式写入密码 |

## 1. 环境选型：为什么是 Kali 虚拟机 + Docker

同一个靶场，装在哪里差别很大。

| 方案 | 隔离性 | 上手成本 | 打崩后的恢复 | 结论 |
|---|---|---|---|---|
| Windows 直装 phpStudy | ❌ 无 | 低 | 手工清理 | 能跑，但 RCE 类模块等于在自己日常系统上执行陌生代码 |
| Windows + Docker Desktop | ⚠️ 容器级 | 中 | 删容器 | 可接受 |
| WSL2 + Docker | ⚠️ 容器级 | 中 | 删容器 | 可接受 |
| **Kali 虚拟机 + Docker** | ✅ 整机级 | 中 | **快照回滚** | **推荐** |

选 Kali 虚拟机的三个理由：

1. **隔离是整机级的**：打穿了只是虚拟机，宿主机没事；
2. **快照 = 时间机器**：装好打一张，练崩了回滚，比手工卸载干净一百倍；
3. **攻防工具同机**：Kali 自带 Firefox、Burp Suite、sqlmap，抓包不用跨机器配代理链。

至于"皮卡丘装在哪会不会伤电脑"——**程序本身无害**，风险来自两件人为的事：

- **对外暴露**：Apache 监听 `0.0.0.0` 又桥接上网，等于把靶场挂到局域网；
- **练习自伤**：RCE、文件上传这些模块会真的执行命令、真的写 webshell 文件，残留下来就是后门。

所以本文所有命令都守着同一条底线：**只监听 `127.0.0.1`，虚拟机网络用 NAT，不桥接。**

## 2. 准备虚拟机

### 2.1 配置

- 虚拟化软件：VMware Workstation（个人免费）或 VirtualBox；
- 镜像：<https://www.kali.org/get-kali/> → **Virtual Machines** 下预构建镜像，比 ISO 装省 20 分钟；
- 建议：**2 vCPU / 4 GB 内存 / 40 GB 磁盘**（低于 2 GB 跑 Docker + 浏览器会明显卡）；
- 网络：**先保持默认 NAT**。

预构建镜像默认账号密码都是 `kali` / `kali`，**第一次登录立刻 `passwd` 改掉**。

### 2.2 首启三件事

```bash
sudo apt update && sudo apt full-upgrade -y   # Kali 是滚动发行版，首次更新较慢
ip a                                          # 看网卡和 IP
ping -c 3 www.kali.org                        # 确认能上网
```

### 2.3 打第一张快照 `00-clean-base`

系统更新完、靶场还没装的时候拍一张。后面所有折腾都从这里回滚。

> **这一步别省。** 它是"敢动手"的前提——知道自己随时能退回去，才敢在系统上乱试。

## 3. 安装 Docker

```bash
sudo apt install -y docker.io
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
```

### 3.1 安装时冒出的蓝色对话框

装 `docker.io` 时，debconf 会弹一个全屏对话框：

```
┌───────────────────────┤ Configuring docker.io ├───────────────────────┐
│ Automatically remove Docker data if package is purged?                │
│                                                                       │
│                          <Yes>              <No>                      │
└───────────────────────────────────────────────────────────────────────┘
```

**选 `<No>`**（默认就是 No，直接 Enter 即可）。含义是：卸载 docker 包时，是否顺便删掉 `/var/lib/docker` 里的镜像和容器数据。留着它，以后重装不用重新拉镜像。

选错了也不要紧：

```bash
sudo dpkg-reconfigure docker.io
```

### 3.2 组权限必须重新登录

`usermod -aG docker` 改的是用户组，**当前 shell 不会自动生效**。不注销重登，后面每条 docker 命令都会报：

```
permission denied while trying to connect to the Docker daemon socket at unix:///var/run/docker.sock
```

不想注销的话，可以临时 `newgrp docker`，但新开的终端仍然要重登。

### 3.3 验证三连

```bash
docker --version                  # 有版本号
systemctl status docker           # active (running)
docker run --rm hello-world       # 能跑通，说明权限也对了
```

`systemctl status` 里看到 `containerd.service is disabled` 是 Kali 打包的正常提示，不影响使用。

> 这一步的 `hello-world` 很关键：**它同时也是网络连通性测试**。如果它拉不下来，后面构建一定挂。

---

## 4. 镜像加速：国内网络的必修课

`hello-world` 卡住不动，基本就是连不上 `registry-1.docker.io`。先确认：

```bash
curl -I --max-time 10 https://registry-1.docker.io/v2/
```

超时或返回 `401/403` 之外的异常，就配加速器：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://hub.rat.dev"
  ]
}
EOF
sudo systemctl daemon-reload
sudo systemctl restart docker
docker info | grep -A3 "Registry Mirrors"
```

再 `docker pull hello-world` 试。**60 秒还没动静就 Ctrl+C 换源**，别死磕——加速器失效是常态。

常见报错对照：

| 报错 | 原因 | 处理 |
|---|---|---|
| `no such host` | 容器内 DNS 解析失败 | 改 `/etc/resolv.conf` 加 `nameserver 223.5.5.5` |
| `manifest unknown` | 这个源没有该镜像 | 换下一个源 |
| `429 Too Many Requests` | 被限流 | 等几分钟或换源 |
| `x509: certificate ...` | 虚拟机时间不对 | `sudo timedatectl set-ntp true` |
| `TLS handshake timeout` | 需要走代理 | 给 docker 配 `HTTP_PROXY` |

## 5. 坑一：仓库自带的 Dockerfile 跑不起来

到这一步，网上的教程基本都是同一句：`git clone` 然后 `docker build`。我照做了，然后撞上第一个坑。

### 5.1 先看 Dockerfile，别急着 build

```bash
cd ~
git clone --depth 1 https://github.com/zhuifengshaonianhanlu/pikachu.git
cd pikachu
head -40 Dockerfile
```

仓库里的 Dockerfile 大致是这样：

```dockerfile
FROM mattrayner/lamp:latest-2004-php7
# Ubuntu 20.04 + Apache + MySQL + PHP 7.4 + phpMyAdmin 全家桶
COPY . /app/
EXPOSE 80
CMD ["/run.sh"]
```

第一行就值得警惕：`mattrayner/lamp` 停在 2021 年，底层是 **Ubuntu 20.04 (focal)**，早已过了标准支持期。

### 5.2 报错：InvalidBaseImagePlatform

构建失败，日志尾部：

```
ERROR: failed to solve: process "/bin/sh -c ..." did not complete successfully: exit code: 255
```

往上翻，有一条 warning 才是关键：

```
1 warning found (use docker --debug to expand):
 - InvalidBaseImagePlatform: Base image mattrayner/lamp:latest-2004-php7 was pulled
   with platform "linux/arm64", expected "linux/amd64" for current build (Dockerfile:1)
```

**拉下来的是 arm64 镜像，而我的是 x86_64。** 继续跑就变成：

```
exec /bin/sh: exec format error
```

这个报错和 apt 源、网络、权限**一点关系都没有**——CPU 指令集不对，二进制根本执行不了。

### 5.3 为什么加速器会给错架构

Docker Hub 上一个 tag 可以是**多架构 manifest**（同时挂 amd64/arm64）。加速器为了省空间，经常只缓存其中一份，返回时又不校验客户端架构，于是 amd64 的机器拿到了 arm64 的层。

我试过显式指定架构：

```bash
docker pull --platform linux/amd64 mattrayner/lamp:latest-2004-php7
```

返回的仍然是 arm64，还附一句：

```
image with reference ... was found but its platform (linux/arm64)
does not match the specified platform (linux/amd64)
```

**结论：这条路在当前网络环境下走不通。** 换加速器也是一样——不是源的配置问题，是它缓存里根本没有 amd64。

### 5.4 验证方法（比看 tag 可靠）

```bash
docker image inspect mattrayner/lamp:latest-2004-php7 \
  --format '{% raw %}{{.Os}}/{{.Architecture}}{% endraw %}'
```

必须是 `linux/amd64`。**不要相信 tag 名，要看 inspect 的输出。**

> 顺带一个容易困惑的点：`docker rmi` 报 `No such image`，是因为 BuildKit 拉的基础镜像只在**构建缓存**里，不进 `docker images`。清缓存用 `docker builder prune -af`。

## 6. 坑二：bullseye 安全源 404，换源也救不了

放弃全家桶镜像后，思路很简单：用官方 `php:7.4-apache`，再 `apt install mariadb-server` 把数据库装进同一个容器。

构建到 `apt-get update && apt-get install ...` 这一步，退出码 100，日志全是：

```
E: Failed to fetch http://mirrors.aliyun.com/debian-security/pool/updates/main/m/mariadb-10.5/mariadb-server_10.5.29-0+deb11u1_amd64.deb
   404  Not Found
E: Unable to fetch some archives, maybe run apt-get update or try with --fix-missing?
```

### 6.1 第一反应是换源，但没用

`php:7.4-apache` 基于 **Debian bullseye**，`sources.list` 三行：

```
deb http://deb.debian.org/debian bullseye main
deb http://deb.debian.org/debian-security bullseye-security main
deb http://deb.debian.org/debian bullseye-updates main
```

把 `deb.debian.org` 换成阿里云 → 还是 404。换成清华源 → **还是同一个 404，只是域名变了两个字**。

这件事本身就是信息：**如果问题在镜像站，换一个站就该好；换了还一样，说明缺的是文件，不是域名。**

### 6.2 真正的原因

看 404 的路径：`/debian-security/pool/updates/main/m/mariadb-10.5/...`。

bullseye 已经退出标准支持期（转为 oldstable / LTS），Debian 把这批 `pool` 文件下架了，但 **`Packages` 索引里还留着记录**。于是 apt 认为包存在、去下载，所有镜像站都只能回 404。

这就是"换源治不了"的原因：**镜像站是 Debian 的复印件，原件没了，复印件自然也印不出来。**

### 6.3 三种 404 要分清

| 报错 | 含义 | 处理 |
|---|---|---|
| `404 Not Found` + 具体 `.deb` 路径 | 索引有、文件没了（EOL 系统的典型症状） | 换系统版本 / 别装这个包 |
| `Temporary failure resolving` | DNS 问题 | 改 `/etc/resolv.conf` |
| `does not have a Release file` | 源地址或 suite 名写错 | 核对路径 |

判断标准就一句话：**看到具体 `.deb` 文件名 404，就别再换源了。**

## 7. 最终方案：彻底不碰 apt

想通了之后方案反而变简单：**PHP 7.4 镜像里的 `mysqli` 扩展是自带源码编译的，不需要任何 apt 包；数据库也不必塞进同一个容器。**

于是变成两个容器：

```
┌────────────────────── Kali 虚拟机（NAT，不桥接）──────────────────────┐
│                                                                      │
│   Firefox ──► 127.0.0.1:8080 ──┐                                     │
│                                 │                                    │
│                   ┌─────────────▼──────────────┐                     │
│                   │ 容器 pikachu (pikachu:v1)  │                     │
│                   │ php:7.4-apache + mysqli    │                     │
│                   └─────────────┬──────────────┘                     │
│                                 │ mysqli → db:3306                   │
│                   ┌─────────────▼──────────────┐                     │
│                   │ 容器 db (mariadb:10.6)     │                     │
│                   │ 数据卷 /var/lib/mysql      │                     │
│                   └────────────────────────────┘                     │
│                                                                      │
│        两个容器同属自定义网络 pikachu-net，容器名就是主机名            │
└──────────────────────────────────────────────────────────────────────┘
```

这样做的三个好处：

1. **构建不访问任何外部软件源**——`docker build` 的成败不再取决于 Debian 仓库的心情；
2. **数据库用官方镜像**，初始化、健康检查、数据卷都是现成的，不用自己写 `mysqld_safe`；
3. **容器名当域名用**：应用里把 `DBHOST` 写成 `db`，Docker 内置 DNS 直接解析到数据库容器。

### 7.1 `Dockerfile.alt`

```dockerfile
FROM php:7.4-apache

RUN docker-php-ext-install -j"$(nproc)" mysqli pdo_mysql \
 && a2enmod rewrite

COPY . /var/www/html/
COPY entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh && chown -R www-data:www-data /var/www/html

EXPOSE 80
CMD ["/entrypoint.sh"]
```

只有 5 个有效步骤，没有 `apt`，构建 1–2 分钟。

### 7.2 `entrypoint.sh`

容器启动时把数据库配置改对，然后交给 Apache：

```bash
#!/bin/bash
set -e

CFG=/var/www/html/inc/config.inc.php
if [ -f "$CFG" ]; then
    sed -i -E "s/define\('DBHOST'[[:space:]]*,[[:space:]]*'[^']*'\)/define('DBHOST', 'db')/" "$CFG"
    sed -i -E "s/define\('DBPW'[[:space:]]*,[[:space:]]*'[^']*'\)/define('DBPW', 'root')/"   "$CFG"
fi

exec apache2-foreground
```

（为什么是 `define(...)` 而不是 `$dbhost = ...`，见第 8 节——这是第三个坑留下的教训。）

### 7.3 构建与启动

```bash
cd ~/pikachu
chmod +x entrypoint.sh
docker build --platform linux/amd64 -f Dockerfile.alt -t pikachu:v1 .
```

**构建成功的标志**，日志最后一行：

```
=> => naming to docker.io/library/pikachu:v1
```

然后：

```bash
docker network create pikachu-net

docker run -d --name db --network pikachu-net \
  -e MYSQL_ROOT_PASSWORD=root \
  -e MYSQL_DATABASE=pikachu \
  mariadb:10.6

docker run -d --name pikachu --network pikachu-net \
  -p 127.0.0.1:8080:80 \
  pikachu:v1
```

`-p 127.0.0.1:8080:80` 的意思是：**只在 Kali 本机的 8080 上开放**。这是整套方案的安全底线，别写成 `-p 8080:80`。

### 7.4 三步验证

```bash
docker ps                                # 两个容器都是 Up
docker logs --tail 10 db                 # 看到 "mariadb: ready for connections"
curl -I http://127.0.0.1:8080/           # HTTP/1.1 200 OK（或 302）
```

镜像大小参考：`pikachu:v1` **474 MB**，`mariadb:10.6` 约 400 MB。

最后浏览器打开 <http://127.0.0.1:8080/install.php>，点「安装」。

## 8. 坑三：`define()` 常量，`sed` 静默失败

点安装，页面红字：

```
数据连接失败，请检查config.inc.php中的配置
```

按常理排查——`config.inc.php` 里应该是 `$dbhost = '127.0.0.1'` 这种变量。我写了条 `sed` 去改，跑完没报错，页面还是失败。

### 8.1 关键一步：先证明"库是通的"

不猜配置，直接用 PHP 连一次：

```bash
docker exec pikachu php -r '$c=@mysqli_connect("db","root","root","pikachu",3306);
  echo $c ? "连接成功\n" : mysqli_connect_error()."\n";'
```

输出 `连接成功`。

**这一条把排查面砍掉了一半**：数据库在跑、网络通、账号密码对、库存在。问题只可能出在"应用读到的配置值"上。

### 8.2 `grep` 一行都没输出

```bash
docker exec pikachu grep -nE "dbuser|dbpass|dbname|dbhost" /var/www/html/inc/config.inc.php
```

**空输出。** 这说明文件里根本没有这些变量名——之前的 `sed` 一直在匹配一个不存在的东西，所以"成功"退出、什么也没改。

`cat` 出来才看到真相：

```php
define('DBHOST', '127.0.0.1');
define('DBUSER', 'root');
define('DBPW',   'root');
define('DBNAME', 'pikachu');
define('DBPORT', '3306');
```

`install.php` 第 19/22 行用的是：

```php
mysqli_connect(DBHOST, DBUSER, DBPW);
```

**是常量，不是变量。**

### 8.3 修复

```bash
docker exec pikachu sed -i \
  "s/define('DBHOST', '127.0.0.1')/define('DBHOST', 'db')/" \
  /var/www/html/inc/config.inc.php

docker exec pikachu grep -n DBHOST /var/www/html/inc/config.inc.php
# 期望：define('DBHOST', 'db');
```

**不用重启容器**——PHP 每个请求都会重新读文件，刷新页面即可。

> 教训：`sed` 是**静默的**。匹配不上不报错、退出码 0，看起来像成功了。
> 所以每次 `sed -i` 之后必须跟一条 `grep` 验证，否则你改的可能是空气。

## 9. 坑四：`DBPW` 是空字符串

改完 `DBHOST`，刷新——**还是失败**。

### 9.1 把五个常量全打出来

```bash
docker exec pikachu php -r 'include "/var/www/html/inc/config.inc.php";
  var_dump(DBHOST, DBUSER, DBPW, DBNAME, DBPORT);'
```

输出：

```
string(2) "db"
string(4) "root"
string(0) ""        ← 空字符串
string(7) "pikachu"
string(4) "3306"
```

再连一次库：

```
Access denied for user 'root'@'172.18.0.3' (using password: NO)
```

`using password: NO` 就是铁证：**密码根本没传**，因为它是空串。

`172.18.0.3` 是应用容器在 `pikachu-net` 里的地址——顺带也证明了容器网络是通的。

### 9.2 修复

```bash
docker exec pikachu sed -i \
  "s/define('DBPW', '')/define('DBPW', 'root')/" \
  /var/www/html/inc/config.inc.php

docker exec pikachu php -r 'include "/var/www/html/inc/config.inc.php";
  $c=@mysqli_connect(DBHOST,DBUSER,DBPW,DBNAME,DBPORT);
  echo $c ? "OK\n" : mysqli_connect_error(),"\n";'
```

输出 `OK` 就成了。刷新安装页：

```
数据库连接成功！
新建数据库 pikachu 成功！
创建数据库数据成功！
```

### 9.3 别忘了同步源码

容器里改的是一次性的，**重建镜像就没了**：

```bash
sed -i "s/define('DBHOST', '127.0.0.1')/define('DBHOST', 'db')/" ~/pikachu/inc/config.inc.php
sed -i "s/define('DBPW', '')/define('DBPW', 'root')/" ~/pikachu/inc/config.inc.php
grep -nE "DBHOST|DBPW" ~/pikachu/inc/config.inc.php
```

`entrypoint.sh` 里那两条 `sed` 也是为此存在的——**让重建镜像后的配置自动正确**，而不是靠记忆手工改。

## 10. 一键复现

把上面的步骤串成一个脚本（`bash build-pikachu.sh`，假设宿主是 x86_64）：

```bash
#!/usr/bin/env bash
set -euo pipefail

cd ~
[ -d pikachu ] || git clone --depth 1 https://github.com/zhuifengshaonianhanlu/pikachu.git
cd pikachu

cat > entrypoint.sh <<'ENTRY'
#!/bin/bash
set -e
CFG=/var/www/html/inc/config.inc.php
if [ -f "$CFG" ]; then
    sed -i -E "s/define\('DBHOST'[[:space:]]*,[[:space:]]*'[^']*'\)/define('DBHOST', 'db')/" "$CFG"
    sed -i -E "s/define\('DBPW'[[:space:]]*,[[:space:]]*'[^']*'\)/define('DBPW', 'root')/"   "$CFG"
fi
exec apache2-foreground
ENTRY
chmod +x entrypoint.sh

cat > Dockerfile.alt <<'DOCKER'
FROM php:7.4-apache
RUN docker-php-ext-install -j"$(nproc)" mysqli pdo_mysql \
 && a2enmod rewrite
COPY . /var/www/html/
COPY entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh && chown -R www-data:www-data /var/www/html
EXPOSE 80
CMD ["/entrypoint.sh"]
DOCKER

docker build --platform linux/amd64 -f Dockerfile.alt -t pikachu:v1 .

docker network create pikachu-net 2>/dev/null || true
docker rm -f pikachu db 2>/dev/null || true

docker run -d --name db --network pikachu-net \
  -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=pikachu mariadb:10.6

docker run -d --name pikachu --network pikachu-net \
  -p 127.0.0.1:8080:80 pikachu:v1

until docker logs db 2>&1 | grep -q "ready for connections"; do sleep 2; done

echo "构建完成，打开 http://127.0.0.1:8080/install.php"
curl -s -o /dev/null -w "首页 HTTP 状态码：%{http_code}\n" http://127.0.0.1:8080/
```

> 事后看还能再优化一处：`COPY . /var/www/html/` 会把 `Dockerfile.alt`、`entrypoint.sh`、构建日志一起拷进网站根目录。
> 加一个 `.dockerignore`（排除 `*.log`、`Dockerfile*`），或改成 `COPY index.php install.php inc/ vul/ pkxss/ ...` 逐个复制会更干净。

## 11. 日常使用

### 11.1 启停顺序

```bash
docker start db && sleep 3 && docker start pikachu   # 先库，后应用
docker ps
docker stop pikachu db                               # 练完停掉，省约 700 MB 内存
```

数据不会丢：`mariadb` 镜像的 `/var/lib/mysql` 是 Docker 卷，`docker start` 就还在。

容器**不会开机自启**，这是故意的——靶场不该常驻。

### 11.2 配 Burp 抓包

1. Burp 监听 `127.0.0.1:8081`（**别用 8080，和靶场冲突**）；
2. Firefox 装 FoxyProxy，加代理 `127.0.0.1:8081`，只对 `127.0.0.1` 生效；
3. 打开靶场，Burp 里就能看到请求。

### 11.3 数据操作与重置

```bash
# 进库
docker exec -it db mariadb -uroot -proot pikachu

# 备份 / 恢复
docker exec db mariadb-dump -uroot -proot pikachu > ~/pikachu-backup.sql
docker exec -i db mariadb -uroot -proot pikachu < ~/pikachu-backup.sql

# 只重置数据（保留镜像，30 秒）
docker rm -f pikachu db
docker network rm pikachu-net 2>/dev/null
# 再跑第 10 节那两条 docker run
```

> **`/install.php` 不要重复点。** 它会 `DROP DATABASE` 重建，练到一半点一下，进度全没。
> 装好之后可以直接删掉：`docker exec pikachu rm /var/www/html/install.php`。

### 11.4 快照纪律

| 快照 | 时机 | 用途 |
|---|---|---|
| `00-clean-base` | 系统更新完、靶场未装 | 彻底重装的起点 |
| `02-pikachu-ready` | 靶场能打开首页 | **日常回滚点** |

**每练完一关，直接回滚到 `02-pikachu-ready`**，不要一层层叠新快照。回滚会把 webshell、改过的数据库、上传的测试文件一起清掉，比手工清理可靠。

注意：**回滚连你后来写的笔记一起清**。解题记录存宿主机或网盘。

## 12. 排错速查表

| 现象 | 先查这个 | 处理 |
|---|---|---|
| 浏览器打不开 | `docker ps` | 容器没启动 → `docker start db pikachu` |
| 页面空白 / 500 | `docker logs --tail 30 pikachu` | PHP 报错，日志里有文件行号 |
| 「数据连接失败」 | `docker ps` 里 `db` 是否 Up | 先等 5 秒；仍失败见下一行 |
| 连接失败但 `db` 正常 | `docker exec pikachu php -r 'include "/var/www/html/inc/config.inc.php"; var_dump(DBHOST,DBUSER,DBPW);'` | `DBHOST` 必须是 `"db"`，`DBPW` 必须是 `"root"` |
| `port is already allocated` | `sudo ss -lntp \| grep 8080` | 换端口：`-p 127.0.0.1:8090:80` |
| 容器起来又立刻退出 | `docker logs pikachu` | 常见是 entrypoint 没执行权限（重建时 `chmod +x`） |
| `404` 但容器在跑 | `docker exec pikachu ls /var/www/html` | 源码没拷进去，检查 `COPY` 路径 |
| 构建报 `exec format error` | `docker image inspect ... --format '{% raw %}{{.Os}}/{{.Architecture}}{% endraw %}'` | 架构不对，见第 5 节 |
| `apt` 报具体 `.deb` 404 | 看路径里的 suite | EOL 系统，别装 apt 包，见第 6 节 |
| `sed` 改了没效果 | `grep` 一下真实内容 | 匹配表达式和文件里的写法不一致，见第 8 节 |

## 13. 复盘：五条可迁移的方法

这次真正值钱的不是"Pikachu 怎么装"，而是这五条以后装任何东西都用得上的经验。

**1. 读"失败的那一行"，不是最后一行。**
`exit code 255` 什么信息都没有；真正的答案在它上面那条 `InvalidBaseImagePlatform`。

**2. 报错文字常常直接写出根因。**
`exec format error` = 架构不对；`using password: NO` = 密码为空。这种句子不要跳过，先把它翻译成人话。

**3. 换源只能治域名，治不了文件不存在。**
换了一个镜像站还报同样的 404，就该怀疑"原件没了"，而不是继续换第三个站。

**4. `sed -i` 是静默的，必须 `grep` 验证。**
更进一步：改之前先 `cat` 看真实写法。我猜的是 `$dbhost`，实际是 `define('DBHOST')`——猜错不会报错，只会让你在错误的路上多走半小时。

**5. 把大问题切成可单独验证的小问题。**
页面连不上库，可以拆成"PHP 能不能连库"和"应用读到的配置对不对"两步。一条 `php -r` 直连就把范围砍掉一半，比反复刷新页面猜有效得多。

还有一条附赠的：**依赖越少，越可复现。** 最终方案的价值不只是"绕过了 404"，而是构建过程**完全不依赖外部软件源**——半年后重跑，它还是能过。

## 14. 装好之后怎么练

建议顺序（由易到难）：

1. **暴力破解** —— 熟悉 Burp Intruder、字典、响应长度差异；
2. **SQL 注入** —— 联合查询 → 报错注入 → 盲注；
3. **XSS** —— 反射型 → 存储型 → DOM 型；
4. **CSRF** —— 理解"浏览器自动带 Cookie"这件事；
5. **文件上传 / 文件包含 / 目录遍历** —— 绕过思路最多的一组；
6. **RCE、SSRF、XXE、反序列化、越权** —— 难度最高，放最后。

每一关都走同一个循环：

```
看提示 → Burp 抓包 → 猜 payload → 打进去 → 读源码验证
```

**最后一步别跳。** Pikachu 的每一关都是"故意写错的一小段代码"，就在 `vul/` 目录里。看懂它错在哪，换个应用你也能认出来；只记住 payload，换个环境就废了。
